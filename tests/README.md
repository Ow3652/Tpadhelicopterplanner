# ชุดทดสอบ Playwright (v4.0.x – v4.1.x)

สคริปต์ t1200–t3002 คือสคริปต์ทดสอบที่ใช้ระหว่างพัฒนา SIM / HSI / FMS / Direct to
ย้ายมาจากพื้นที่ทำงานบนเว็บ **ยังไม่เคยรันบน PC เครื่องนี้**

## ข้อควรรู้ก่อนรัน
- ทุกสคริปต์เปิดเพจที่ `http://localhost:8765/` และ **ระบุชื่อไฟล์ HTML ตายตัว** (เช่น `Tpad helicopter planner v4.1.3.html`)
  ต้องแก้ชื่อไฟล์ในสคริปต์ให้ตรงกับเวอร์ชันปัจจุบัน (v4.1.4) ก่อน
- สคริปต์แต่ละตัวทดสอบเรื่องเฉพาะ (เช่น t2800 = Direct to/ลบ/แทรกใน FMS ระหว่าง SIM,
  t2100 = ส่วนโค้ง Direct to, t1601 = ความแม่นการเลี้ยว, t3000/t3002 = ความถี่การวาด)
  ผลลัพธ์พิมพ์ที่หน้าจอ ต้องอ่านเอง ไม่มีระบบ pass/fail อัตโนมัติ
- เป็นการจำลองด้วย Chromium ไม่ใช่ iPad หรือ GPS จริง

## วิธีรัน (ใน PowerShell ที่โฟลเดอร์ TPAD)
1. ติดตั้ง Node.js และ Python (ถ้ายังไม่มี)
2. ติดตั้ง Playwright:  `npm install playwright` แล้ว `npx playwright install chromium`
3. เปิดเซิร์ฟเวอร์ (หน้าต่างแรก):  `python -m http.server 8765`
4. รันสคริปต์ (อีกหน้าต่าง):  `node tests\t2800.js`

## t4200.js (v4.2.0)
ทดสอบ METAR_URL และรหัสต่อคนด้วย Apps Script จำลอง ต้องมีไฟล์ `orig.html` (สำเนาของไฟล์ v4.2.0) และ `withurl.html` (สำเนาที่แก้ `const METAR_URL="https://script.google.com/macros/s/METARID/exec"`) ในโฟลเดอร์เดียวกับเซิร์ฟเวอร์

## t4300.js (v4.3.0, PWA)
ทดสอบ service worker (ติดตั้ง, แคช, เปิดตอนออฟไลน์, แถบแจ้งอัปเดตแบบให้ผู้ใช้เลือก, ไฟล์ file://) ไม่ต้องเปิดเซิร์ฟเวอร์เอง สคริปต์เปิดเซิร์ฟเวอร์ชั่วคราวที่พอร์ต 8767 และหาไฟล์แอปล่าสุดในโฟลเดอร์ TPAD กับไฟล์ใน `pwa\` ให้เอง รัน `node tests\t4300.js` จาก TPAD ตรวจด้วยว่า `VERSION` ใน sw.js ตรงกับเลขเวอร์ชันของแอป

## t4301.js (v4.4.0)
ตรวจหัวหน้าจอ: แถวบน (ลิงก์คู่มือ, ปุ่มแผนที่ออฟไลน์, ข้อความ/ช่องกรอกรหัส, ชื่อ user) อยู่แนวเดียวกัน, ปุ่มแผนที่เต็มจออยู่ขวาสุดของแถวแท็บ ระดับเดียวกับแท็บ ขอบขวาตรงช่องรหัส แท็บไม่ต้องเลื่อน (iPad Pro 11 และ iPad gen 9 กว้าง 810), ลำดับปุ่มแผนที่เต็มจอ ☰ เมนู → ย้อนกลับ → ทำซ้ำ → ✕ (v4.4.1 b2: ตรวจเพิ่มว่าปุ่มแถวที่สองของเมนูเต็มจอสูงเท่าแถวบนบนจอสัมผัส และปุ่มเมนูเต็มจอไม่ถูกกล่องข้อมูล/กล่องพิกัดทับบน iPad) ต้องเปิดเซิร์ฟเวอร์พอร์ต 8765 และตั้งตัวแปร FILE

## t4400.js (v4.4.0, แผนที่ออฟไลน์)
ทดสอบการเก็บภาพแผนที่อัตโนมัติ/ดาวน์โหลดตามพื้นที่/ลบ/เพดานขนาด/ใช้ตอนออฟไลน์/ลิงก์คู่มือ ใช้ภาพแผนที่จำลองผ่าน `context.route` (ต้องตั้ง `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1` ซึ่งสคริปต์ตั้งให้เอง เพื่อดักคำขอจาก service worker) ไม่ใช้เครือข่ายจริง รัน `node tests\t4400.js` (ใช้ไฟล์แอปล่าสุดและโฟลเดอร์ `pwa\` อัตโนมัติ)

## t4410.js (v4.4.1, ขยายภาพแผนที่แม่)
ทดสอบว่าเมื่อโหลดภาพแผนที่ระดับซูมปัจจุบันไม่ได้ (เซิร์ฟเวอร์ไม่มีภาพเกินซูมสูงสุด / ออฟไลน์ซูมลึกกว่าที่มีในแคช) จะแสดงแผ่นระดับซูมต่ำกว่าที่ขยายและตัดถูกตำแหน่ง ทั้งตอนแพนแผนที่ ถอยไม่เกิน 6 ระดับ แจ้งเตือนออฟไลน์ตามเดิมเมื่อไม่มีภาพเลย และรีเฟรชแผนที่แล้วกลับเป็นปกติ ใช้ภาพแผนที่จำลอง เปิดเซิร์ฟเวอร์ชั่วคราวพอร์ต 8769 เอง รัน `node tests\t4410.js`
(ใน v4.4.1 ปรับ T6 ของ t4400.js ให้นับเฉพาะแผ่นระดับซูมจริง เพราะแผ่นนอกพื้นที่ดาวน์โหลดจะแสดงจากแผ่นแม่แทน)

## t4600.js (v4.6.0, FLTA + ความสูงตรงเป้าชี้)
ทดสอบการเตือนภูมิประเทศข้างหน้า: บินเข้าหาภูเขาจำลอง (CAUTION ≤120 วินาที, WARNING ≤60 วินาที) บินผ่าน/หันออก (ไม่เตือน) ความเร็วต่ำกว่า 20 kt (งดเตือน) บินสูงพ้น (ไม่เตือน) ความสูง GPS ระดับคงที่/ลดระดับ ออฟไลน์ไม่มีข้อมูล ปิด FLTA แล้วแถบ/กรวยหาย เสียงเตือน (ตัวแทน speechSynthesis) แถบเตือนไม่บังปุ่มบน iPad และกล่องพิกัดแสดงความสูง ft ตรงเมาส์ (PC) และกากบาทกลางจอ (iPad) ใช้ภูเขาจำลองชุดเดียวกับ t4500 ไม่ต่อเครือข่ายจริง เปิดเซิร์ฟเวอร์ชั่วคราวเอง รัน `node tests\t4600.js`

## t4500.js (v4.5.0, ภูมิประเทศ TAWS + กราฟความสูง)
ทดสอบชั้น TAWS (สีแดง/เหลืองเทียบความสูงบิน แสดงบนจอจริง ค่าตั้งเก็บ/ซิงก์) การถอดค่าความสูง Terrarium กราฟความสูงตามเส้นทาง (ค่าสูงสุด ตารางรายช่วง แตะกราฟ) ไม่บังแถบปุ่ม ข้อมูลความสูงในแคชอัตโนมัติ/ใช้ตอนออฟไลน์/ดาวน์โหลดตามพื้นที่ (ถึงซูม 12) ปุ่มบน iPad และความเร็ววาดบน iPad จำลอง (CPU ช้า 4 เท่า) ใช้ "ภูเขาจำลอง" สูง 1,500 ม. ที่ 14.00N 100.80E ส่งผ่าน `context.route` ไม่ต่อ AWS จริง เปิดเซิร์ฟเวอร์ชั่วคราวพอร์ต 8770 เอง รัน `node tests\t4500.js` (ตั้ง `SHOT=1` เพื่อบันทึกภาพหน้าจอไว้ใน /tmp)
