# ชุดทดสอบ Playwright (v4.0.x – v4.1.x)

สคริปต์ t1200–t3002 คือสคริปต์ทดสอบที่ใช้ระหว่างพัฒนา SIM / HSI / FMS / Direct to
ย้ายมาจากพื้นที่ทำงานบนเว็บ **ยังไม่เคยรันบน PC เครื่องนี้**

## ข้อควรรู้ก่อนรัน
- ทุกสคริปต์เปิดเพจที่ `http://localhost:8765/` และ **ระบุชื่อไฟล์ HTML ตายตัว** (เช่น `Tpad helicopter planner v4.1.3.html`)
  ต้องแก้ชื่อไฟล์ในสคริปต์ให้ตรงกับเวอร์ชันปัจจุบัน (v4.1.4) ก่อน
- สคริปต์แต่ละตัวทดสอบเรื่องเฉพาะ (เช่น t2800 = Direct to/ลบ/แทรกใน FMS ระหว่าง SIM,
  t2100 = ส่วนโค้ง Direct to, t1601 = ความแม่นการเลี้ยว, t3000/t3002 = ความถี่การวาด)
  ผลลัพธ์พิมพ์ที่หน้าจอ ต้องอ่านเอง ไม่มีระบบ pass/fail อัตโนมัติ
- เป็นการจำลองด้วย Chromium ไม่ใช่ iPad หรือ GPS จริง

## วิธีรัน (ใน PowerShell ที่โฟลเดอร์ TPAD)
1. ติดตั้ง Node.js และ Python (ถ้ายังไม่มี)
2. ติดตั้ง Playwright:  `npm install playwright` แล้ว `npx playwright install chromium`
3. เปิดเซิร์ฟเวอร์ (หน้าต่างแรก):  `python -m http.server 8765`
4. รันสคริปต์ (อีกหน้าต่าง):  `node tests\t2800.js`

## t4300.js (v4.3.0, PWA)
ทดสอบ service worker (ติดตั้ง, แคช, เปิดตอนออฟไลน์, แถบแจ้งอัปเดตแบบให้ผู้ใช้เลือก, ไฟล์ file://) ไม่ต้องเปิดเซิร์ฟเวอร์เอง สคริปต์เปิดเซิร์ฟเวอร์ชั่วคราวที่พอร์ต 8767 และหาไฟล์แอปล่าสุดในโฟลเดอร์ TPAD กับไฟล์ใน `pwa\` ให้เอง รัน `node tests\t4300.js` จาก TPAD ตรวจด้วยว่า `VERSION` ใน sw.js ตรงกับเลขเวอร์ชันของแอป

## t4301.js (v4.4.0)
ตรวจหัวหน้าจอ: แถวบน (ลิงก์คู่มือ, ปุ่มแผนที่ออฟไลน์, ข้อความ/ช่องกรอกรหัส, ชื่อ user) อยู่แนวเดียวกัน, ปุ่มแผนที่เต็มจออยู่ขวาสุดของแถวแท็บ ระดับเดียวกับแท็บ ขอบขวาตรงช่องรหัส แท็บไม่ต้องเลื่อน (iPad Pro 11 และ iPad gen 9 กว้าง 810), ลำดับปุ่มแผนที่เต็มจอ ☰ เมนู → ย้อนกลับ → ทำซ้ำ → ✕ (v4.4.1 b2: ตรวจเพิ่มว่าปุ่มแถวที่สองของเมนูเต็มจอสูงเท่าแถวบนบนจอสัมผัส และปุ่มเมนูเต็มจอไม่ถูกกล่องข้อมูล/กล่องพิกัดทับบน iPad) ต้องเปิดเซิร์ฟเวอร์พอร์ต 8765 และตั้งตัวแปร FILE

(ใน v4.4.1 ปรับ T6 ของ t4400.js ให้นับเฉพาะแผ่นระดับซูมจริง เพราะแผ่นนอกพื้นที่ดาวน์โหลดจะแสดงจากแผ่นแม่แทน)
